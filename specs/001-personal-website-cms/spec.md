# Feature Specification: 个人网站内容管理系统

**Feature Branch**: `001-personal-website-cms`

**Created**: 2026-07-28

**Status**: Draft

**Input**: User description: "这个网站可以自己选择头像，有管理端我个人使用，客户端仅仅展示不可修改，管理端可以修改头像图片背景图片等，管理端通过账号密码登录，添加作品展示页面支持图片轮播，支持深色浅色切换"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 访问者浏览个人网站 (Priority: P1)

任何访问者打开网站后，可以看到个人网站的完整展示内容，包括头像、背景图片、个人信息和作品展示。访问者只能查看，无法修改任何内容。

**Why this priority**: 这是网站的核心价值——向外界展示个人形象和作品。没有这个功能，网站就没有存在的意义。

**Independent Test**: 打开网站首页即可看到完整的个人展示页面，包括头像、背景图和个人信息，无需登录即可访问。

**Acceptance Scenarios**:

1. **Given** 访问者首次打开网站, **When** 页面加载完成, **Then** 看到个人头像、背景图片、个人简介等展示内容
2. **Given** 访问者在浏览网站, **When** 尝试修改任何内容（如点击图片、文本）, **Then** 无法触发任何编辑功能，页面仅为只读展示
3. **Given** 管理端已更新头像和背景图, **When** 访问者刷新页面, **Then** 看到更新后的头像和背景图

---

### User Story 2 - 管理员登录管理端 (Priority: P2)

网站所有者（管理员）通过独立的登录页面，使用账号和密码登录管理端，获得内容修改权限。

**Why this priority**: 管理端是内容更新的唯一入口，必须先有登录功能才能保护管理权限，防止未授权修改。

**Independent Test**: 访问管理端登录页面，输入正确的账号密码后可进入管理界面；输入错误凭据则被拒绝访问。

**Acceptance Scenarios**:

1. **Given** 管理员在登录页面, **When** 输入正确的账号和密码并提交, **Then** 成功登录并跳转到管理端仪表盘
2. **Given** 管理员在登录页面, **When** 输入错误的账号或密码并提交, **Then** 显示错误提示，无法进入管理端
3. **Given** 管理员已登录, **When** 长时间未操作（会话过期）, **Then** 自动退出登录，需要重新验证身份
4. **Given** 未登录用户, **When** 直接访问管理端 URL, **Then** 被重定向到登录页面

---

### User Story 3 - 管理员修改网站内容 (Priority: P2)

管理员登录后，可以在管理端修改个人头像、背景图片、个人简介等网站展示内容，修改保存后立即在客户端生效。

**Why this priority**: 这是管理端的核心功能，让网站所有者能够自主更新个人展示内容，保持网站的时效性。

**Independent Test**: 登录管理端后上传新头像，保存后在客户端页面验证头像已更新。

**Acceptance Scenarios**:

1. **Given** 管理员在管理端, **When** 上传一张新头像图片并保存, **Then** 客户端网站展示新头像
2. **Given** 管理员在管理端, **When** 上传一张新背景图片并保存, **Then** 客户端网站展示新背景图
3. **Given** 管理员在管理端, **When** 修改个人简介文字并保存, **Then** 客户端网站展示更新后的个人简介
4. **Given** 管理员在管理端, **When** 上传超大或非图片格式文件作为头像, **Then** 系统提示文件格式或大小不符合要求

---

### User Story 4 - 作品展示与图片轮播 (Priority: P3)

访问者可以在作品展示页面浏览管理员的代表作品，作品以图片轮播形式展示，支持手动切换和自动播放。

**Why this priority**: 作品展示是个人网站的重要功能，能有效展示个人能力和经验，但需要先有基本的内容管理框架（P1、P2）。

**Independent Test**: 在客户端页面查看作品展示区域，可以看到多张作品图片轮播，并能手动前后切换。

**Acceptance Scenarios**:

1. **Given** 访问者在作品展示页面, **When** 页面加载完成, **Then** 看到作品图片自动轮播展示
2. **Given** 访问者在作品展示页面, **When** 点击左右切换按钮, **Then** 切换到上一张或下一张作品图片
3. **Given** 访问者在作品展示页面, **When** 点击底部的指示器圆点, **Then** 跳转到对应的作品图片
4. **Given** 管理员在管理端, **When** 上传新的作品图片并填写作品信息, **Then** 作品展示页面新增该作品
5. **Given** 管理员在管理端, **When** 删除某张作品图片, **Then** 作品展示页面不再显示该作品

---

### Edge Cases

- 管理端上传的图片文件过大时如何处理？系统应限制文件大小并给出明确提示
- 管理端账号被暴力破解怎么办？系统应在连续多次登录失败后临时锁定账号
- 没有作品时，作品展示区域应显示友好的空状态提示
- 图片加载失败时，轮播组件应显示占位图而不是空白
- 管理员修改内容时网络中断，应提示保存失败并保留已填写的修改内容
- 多个设备同时登录同一个管理账号时的行为——允许但需要在安全敏感操作时重新验证

## Requirements *(mandatory)*

### Functional Requirements

**客户端（展示端）**:
- **FR-001**: 系统必须展示个人头像、背景图片和个人简介信息
- **FR-002**: 客户端所有页面必须是只读的，不提供任何编辑入口
- **FR-003**: 系统必须以图片轮播形式展示作品集，支持自动播放和手动切换

**管理端**:
- **FR-007**: 系统必须提供独立的登录页面，通过账号和密码验证管理员身份
- **FR-008**: 系统必须在连续登录失败达到阈值（5次）后锁定账号 15 分钟
- **FR-009**: 系统必须在管理员会话超时（30分钟无操作）后自动退出登录
- **FR-010**: 管理端必须提供头像上传和更换功能
- **FR-011**: 管理端必须提供背景图片上传和更换功能
- **FR-012**: 管理端必须提供作品图片的上传、删除和排序功能
- **FR-013**: 管理端必须支持为每个作品添加标题和描述信息
- **FR-014**: 管理端必须提供个人简介等文本内容的编辑功能
- **FR-015**: 管理端上传图片时必须验证文件格式（仅允许常见图片格式：JPG、PNG、WebP）和文件大小（单张不超过 10MB）

**数据持久化**:
- **FR-016**: 系统必须持久化存储所有管理端修改的内容，确保客户端始终展示最新数据

### Key Entities

- **管理员（Admin）**: 网站的唯一所有者和管理者，拥有账号、密码（加密存储），通过登录获得管理权限
- **网站配置（SiteConfig）**: 网站全局展示配置，包括头像图片、背景图片、个人简介等基本信息
- **作品（PortfolioItem）**: 展示在作品集中的一个作品，包含作品图片、标题、描述和排序位置

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 访问者打开网站后 3 秒内看到完整的首页展示内容
- **SC-002**: 管理员从登录到开始编辑内容的操作流程不超过 1 分钟
- **SC-003**: 管理端保存内容修改后，客户端在 5 秒内可看到更新（刷新页面后）
- **SC-004**: 作品轮播切换动画流畅，手动切换响应时间不超过 300 毫秒
- **SC-005**: 管理端所有上传和保存操作，成功率达到 99% 以上（在正常网络环境下）
- **SC-006**: 网站在主流浏览器（Chrome、Edge、Firefox、Safari）上均能正常展示

## Clarifications

### Session 2026-07-28

- Q: 数据存储方式？ → A: 轻量数据库（SQLite），单文件部署、无需额外服务、支持结构化查询
- Q: 深色/浅色模式取舍？ → A: 移除深色模式切换，遵守 Newsprint 永久浅色模式，保留报纸印刷美学的独特性
- Q: 后端 API 方案？ → A: Next.js 全栈方案，React 前端 + API Routes 后端合一，单项目部署
- Q: 图片存储方式？ → A: 服务器本地文件系统存储，简单直接、零额外成本
- Q: 管理员认证方式？ → A: iron-session + bcrypt，轻量加密 cookie 会话管理 + 密码哈希，适合单用户场景

## Assumptions

- 采用 Next.js 全栈方案（React 前端 + API Routes 后端），数据存储使用 SQLite
- 管理员账号为预设的唯一账号（密码通过 bcrypt 哈希存储），不需要注册功能（网站为个人使用）
- 管理员认证采用 iron-session 加密 cookie 会话机制
- 管理员通过账号密码登录，不需要双因素认证或其他高级安全措施
- 网站面向中文用户，默认语言为中文
- 客户端展示页面响应式设计，适配桌面端和移动端浏览
- 管理端仅需在桌面端使用，不要求移动端适配
- 网站部署在标准 Web 服务器上，用户有基本的服务器运维能力
- 作品图片和上传文件存储在服务器本地文件系统
- 网站视觉风格遵循 Newsprint（新闻纸）设计系统：永久浅色模式、高对比黑白配色、零圆角、网格布局、衬线字体
